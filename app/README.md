# CyTools_AudioLibrary — developer and integrator guide

Standalone CyTool (`cy.tool.audiolibrary`, 0.1.2) built on CyToolsCore 0.10.1. Maintenance: Cyberalien. One runtime, one manifest
(`CyTool.json`, generated by `build_manifest.py`), four façades: Dear ImGui, CLI, JSONL/HTTP, MCP.
No dependency on CyToolsManager, on a GUI for the CLI/MCP paths, or on one AI client.

All commands below are run from the Tool root (the folder that holds `CyTools_AudioLibrary.exe`) in PowerShell.
Every one of them was executed on the validation machine; results are in `Docs/AudioLibrary-Validation.md`.

## Install

The [CyToolsCore SDK](https://github.com/MrMybal/CyToolsCore) 0.10.1 (MIT) is installed by `Install.ps1` from its
public repository, at the exact commit pinned in `app/requirements.txt`, so `git` is needed from the first step. Moving
to a newer SDK means changing that pin and running the tests again. Model weights are never part of the repository: they are downloaded from the *Installation* tab, or with
`install_model`, into `data\models\`.

```powershell
powershell -ExecutionPolicy Bypass -File app\Install.ps1            # base runtime: runtime\python
.\runtime\python\Scripts\python.exe app\setup_backend.py            # AI engine: runtime\engines\torch + pinned sources
.\runtime\python\Scripts\python.exe app\setup_backend.py --status
powershell -ExecutionPolicy Bypass -File app\build_launcher.ps1     # CyTools_AudioLibrary.exe (Visual C++ build tools)
```

The base runtime needs Python >= 3.11 on the machine (it creates the private environments at their final
path). The engine is PyTorch 2.8.0 + cu126 (or `--cpu-only`), pinned in `engine.json` with a constraints
file so that a dependency cannot replace the CUDA build. `git` is needed once for the engine sources.

## Models

```powershell
.\runtime\python\Scripts\python.exe app\tool.py invoke list_models
.\runtime\python\Scripts\python.exe app\tool.py invoke install_model --params '{\"modelKey\":\"laion-clap@htsat-unfused\"}' --timeout 7200
```

Models whose licence needs a personal acceptance (M2D-CLAP: NTT licence; Omni-Embed-Audio: Qwen Research
backbone) fail with `LicenseAcceptanceRequired` until the **user** passes `"acceptLicense": true` — in the
interface, by ticking the box themselves. An agent must ask the user; it must not set this flag on its own.
A Hugging Face token (gated/private custom models only) is stored with
`.\runtime\python\Scripts\python.exe app\maintenance.py login` (read from stdin, kept in the OS credential
store, never in argv, jobs, settings or logs).

| Model key | Role | Adapter | State in this delivery |
|---|---|---|---|
| `m2d-clap@2025` | default audio/text embedding, zero-shot tags | `m2d_clap` | installed, validated |
| `laion-clap@htsat-unfused` | legacy CLAP, second engine | `hf_clap` | installed, validated |
| `omni-embed-audio@qwen3b-cl` | complex queries, negations | `omni_embed` | installed, validated (9.8 GiB VRAM peak) |
| `qwen3-1.7b@2025-04` (default), `qwen3-0.6b`, `qwen3-4b` | query understanding LLM, generic prompt | `hf_causal_lm` | 1.7B validated |
| `cytools-search-assist@v1` (default), `cymetasound-search-assist-0.5b@v1` | query understanding, Qwen2.5 1.5B / 0.5B fine tuned on 4 753 messy queries, GGUF Q8_0 from Hugging Face, shared with CyMetaSound | `hf_causal_lm` (`ggufFile`) | installed from Hugging Face and validated, `promptProfile: caption` |
| `m2d-clap@2024`, `omni-embed-audio@qwen3b-ac` | other versions of the same families | same adapters | not validated |
| `audio-flamingo-3@hf` | deep captioning/reranking | none | declared extension point only |

Custom model or new version: `register_model` (or *Installation > Add a custom model*). It is referenced in
place; `modelId@version` + revision + weights hash + analysis settings form the analysis key, so each
version keeps its own embeddings and index. A brand-new architecture needs one adapter file
(`adapters/base.py` contract) referenced as `file:<adapter.py>`; nothing else in the Tool changes.

## Recommended search setup (measured)

| Models for search | VRAM | Caption test, expected file first | Query time (warm) |
|---|---|---|---|
| M2D-CLAP alone | 0.75 GiB | 3/5 (5/5 in the top 2) | 0.02 s |
| M2D + LAION-CLAP (**default for new Libraries**) | 1.4 GiB | 4/5 | 0.03 s |
| + Omni-Embed on GPU | 10.3 GiB | 4/5 | 0.1 s |
| + Omni-Embed on CPU (**its default device**) | 1.4 GiB, ~14 GB RAM | 4/5 | 2-3 s (51 s first load) |
| Qwen3-1.7B assistant (Auto: long, non-English or negated requests only) | +~3.5 GiB | — | +1.2 s |
| CySearchAssist 1.5B (GGUF Q8_0) | +~3.4 GiB | 92.0 % in the top 5 against 58.0 % raw, on 150 messy queries | +3.4 s warm |
| CySearchAssist 0.5B (GGUF Q8_0) | +~1.2 GiB | 250/250 valid answers, weaker understanding of rare words | +2.2 s warm |

The default model for query understanding is the one named in the application settings (`llmModel`,
*Options* or the *LLM* list of the search bar). It is the same default for the interface, the CLI and
MCP: an assistant that calls `search_sounds` without naming a model gets the one you see on screen.
The catalogue marks `cytools-search-assist@v1` as the default assistant once it is installed (Installation tab).

The two CySearchAssist models are published as GGUF Q8_0 on Hugging Face (`cyberalien/CySearchAssist-CLAP-1.5B` and
`-0.5B`) and read through transformers with the `gguf` package, so no second runtime is needed. Dequantising takes
35 to 45 s, so the first GPU load also writes the dequantised model to `_dequantized/` next to the GGUF (2.9 GB and
0.9 GB); later loads read it in 1 to 2 s, and it is rebuilt if the GGUF changes. Quantisation costs a little: on the
same 150 queries run on this machine, the 1.5B finds the right family in the top 5 for 94.0 % in float16 and 92.0 %
in Q8_0.

### The two prompt profiles

A model declares, in its registry entry, which instruction it was trained for. `generic` is the
built-in prompt with its few-shot examples, used by the Qwen3 entries. `caption` is the schema of the
fine tune: one clean English caption, three variations, and suggested categories and tags. Giving a
fine tune the generic prompt makes it answer worse, which is why the profile is declared rather than
guessed, and why no code anywhere tests a model's name.

Suggested categories are hints, never a filter. Only the ones that exist in the Library's own taxonomy
are used, as a re-ordering bonus on candidates the embeddings already found (`hintBoost`, 0.12 by
default, 0 disables it). On 250 validation queries the bonus moved the expected family from 72.8 % to
87.2 % of first places. That number compares the model with the Library's automatic categories, so it
measures agreement between two models rather than perceptual relevance.

Omni-Embed brought no measurable gain on this small test; keep it unticked for everyday searches and enable it for hard
requests (negations, long descriptions). *Installation > Device for this model* sets a per-model device; indexing a
Library with a model on CPU is much slower than on GPU, so index with GPU, then switch that model to CPU for searching.
Models stay resident `idleUnloadSeconds` (default 300 s) after the last request, then all VRAM is released.

## Use

```powershell
.\CyTools_AudioLibrary.exe                                            # interface
.\runtime\python\Scripts\python.exe app\tool.py describe
.\runtime\python\Scripts\python.exe app\tool.py invoke create_library --params-file lib.json
.\runtime\python\Scripts\python.exe app\tool.py invoke scan_library --params '{\"libraryId\":\"<id>\"}' --timeout 36000
.\runtime\python\Scripts\python.exe app\tool.py invoke analyze_library --params '{\"libraryId\":\"<id>\"}' --timeout 360000
.\runtime\python\Scripts\python.exe app\tool.py invoke search_sounds --params-file search.json
.\runtime\python\Scripts\python.exe app\tool.py --data-dir data\jobs-mcp mcp     # MCP stdio server
```

`lib.json`: `{"name": "My SFX", "cacheLocation": "G:/CyToolsCache/AudioLibrary", "folders": ["D:/Audio/SFX", "E:/GameAudio"]}`.
One runtime per data directory: give the MCP server its own `--data-dir` (as above) when the interface is
open. The Library database itself (SQLite WAL, in the cache) is shared safely between them. The one-shot CLI
reloads models at each call; the interface and the MCP server keep them resident (idle unload after 300 s,
`idleUnloadSeconds` in `data/settings/audiolibrary.json`).

MCP client entry (replace `<tool>` with the absolute path of the Tool root):

```json
{"mcpServers": {"cytools-audiolibrary": {"command": "<tool>/runtime/python/Scripts/python.exe",
  "args": ["<tool>/app/tool.py", "--data-dir", "<tool>/data/jobs-mcp", "mcp"]}}}
```

## Using the Tool from an AI assistant (MCP)

Typical split: the user builds and scans Libraries in the standalone; an assistant connected through MCP searches them
and proposes sounds. The same Library files and caches are shared, so nothing has to be exported.

* Find a sound: `op_search_sounds` with `{"parameters": {"text": "heavy metal door slam, long reverb", "topK": 10}}`. `libraryId` is
  optional: without it every Library is searched and each result carries `libraryName`, the absolute `path` of the
  original file, `duration`, tags, categories, a score per model and `matchedSegment` for long recordings. Poll
  `cy_get_job` until `Completed`, then read `outputs.results`. Any language works (`llmAssist: auto`).
* More like this one: `similarTo` (+ `libraryId`). Narrow down with `filters` (duration, channels, type, category, tag...).
* Manage on request: `op_list_libraries`, `op_create_library`, `op_add_folder`, `op_check_library` (read-only diff),
  `op_scan_library`, `op_analyze_library`, `op_library_status`, `op_update_assets` (user tags, categories, rating,
  favourite, description, notes).
* Work folder by folder: `op_list_folders` returns the tree of a Library with recursive and direct file counts. A path
  from it becomes `filters: {"rootIds": [rootId], "folderPrefix": "Impacts/Metal"}` in `op_browse_assets` (the files)
  or `op_update_assets` (edit the whole folder in one call: `addTags`, `removeTags`, `addCategories`,
  `removeCategories`, `appendNotes`...). An empty filter is refused rather than read as "the whole Library".
* Prepare files for another program: `op_export_bundle` copies `audioIds`, or everything `filters` match, into a
  `destination` folder (`layout` `flat` or `folders`, `bundle.json` listing source, AudioId, tags and categories). It
  only reads the originals, never overwrites, and refuses a destination inside a Library folder or a cache. In the
  interface, the same sounds can also be dragged out of the list (Windows, copy only) into Explorer or Unreal Engine.
* `op_install_model.acceptLicense`, `op_rename_files.confirm`, `op_undo_rename.confirm` and `op_write_metadata.confirm` are the
  user's decisions: ask, show what will change, and only then pass `true`.

## Background synchronisation (standalone)

Each Library has `autoSync` = `auto` (default) | `ask` | `off`, `autoSyncIntervalSeconds` (300) and `autoAnalyze` (true), editable in
the left panel (*Automatic update*) or with `update_library`. The window submits a read-only `check_library` job per Library at
start-up and at each interval; when something changed, `auto` runs `scan_library` (then `analyze_library` for new/modified files
when `autoAnalyze`), `ask` shows a banner with *Update now* / *Ignore*. Missing files are hidden, never purged; an unplugged
drive is reported as unavailable. The MCP server has no timer: an assistant calls `check_library` itself.

## File Tools (the only operations that change original files)

`suggest_names` (read-only plan from category + tags for names like `sound_01`, `ZOOM0012`), `rename_files` (same folder, same
extension, never overwrites, journalled), `undo_rename`, and `write_metadata` (ID3 for WAV/AIFF/MP3, Vorbis comments for
FLAC/OGG/Opus, MP4 atoms for M4A; written into a copy, decoded audio verified identical, then swapped; backup in
`<cache>/Common/FileOperations/Backups`; database identity refreshed so nothing is re-analysed). Audio files have no EXIF:
these tag formats are the audio equivalent. BWF `bext`/iXML chunks (Soundminer-style) are **not** written in this version.
`mutagen` (GPL-2.0-or-later) does the tagging; it is a dependency of the base runtime.

## Release

```powershell
powershell -ExecutionPolicy Bypass -File app\build_launcher.ps1             # CyTools_AudioLibrary.exe, rebuilt from source
.\runtime\python\Scripts\python.exe app\scripts\build_package.py            # every release asset, from the committed code
```

`build_package.py` writes `runtime\build\release\<version>\`: the user package (the committed files, `LICENSE`,
`LICENCES\` and the launcher), `cytools-app.zip` with its `.sha256` (through `build_release.py`), and `SHA256SUMS.txt`.
It refuses to run on uncommitted changes and stops if a licence file would be missing from the package.

The archive holds exactly the files the repository keeps under `app/`, plus `LICENSE`: the list comes from Git and `.gitignore`,
so data, runtimes, model weights, the SDK wheel and local development files never enter it. It is checked with
the application's own update code before the script reports success. Attach `cytools-app.zip`,
`cytools-app.zip.sha256` and the rebuilt launcher to the GitHub release; the Updates tab expects those names.

## Architecture

```text
gui/ (ImGui)   tool.py (35 operations)   CLI / JSONL / HTTP / MCP        <- façades, same Runtime.submit
        \____________ CyToolsCore Runtime: validation, jobs, sessions, scheduler, ledger ____________/
audiolib/library    virtual Library = portable JSON; cache anywhere, movable, never beside the audio
audiolib/scanner    identity (size + fast hash, SHA-256 on demand): new/unchanged/modified/moved/missing/duplicate
audiolib/audiofile  libsndfile + PyAV decoding (no external ffmpeg), BS.1770 loudness
audiolib/waveform   min/max peak pyramid, memory-mapped
audiolib/registry   model descriptors, capabilities, versions, receipts, analysis keys
audiolib/embeddings one store + one index provider per analysis key (flat exact cosine; pluggable)
audiolib/search     per-model retrieval -> weighted Reciprocal Rank Fusion; never mixes embeddings
audiolib/llm        optional query understanding -> stable structured query; deterministic parser fallback
audiolib/taxonomy   editable hierarchical taxonomy, zero-shot softmax labelling per model
audiolib/modelhost  persistent engine worker (registered with Runtime.register_worker)
audiolib/fileops    rename + write tags: the only code that changes original files (confirm, journal, verified copy, backup)
worker.py + adapters/   the only code that imports PyTorch; runs in runtime/engines/torch
```

**What the SDK lacked.** CyToolsCore (0.9.0 when this was written, still so in 0.10.1) ships a one-shot `ProcessWorker`; a search cannot reload a model
per query. `audiolib/modelhost.py` is a persistent JSONL worker with real cancellation (the process is killed
and reaped before the job reports `Cancelled`) and idle unload. It uses the Core's own worker contract
(`register_worker`, `release`, `health`), so it is not a second scheduler. A generic *persistent worker with
handshake/heartbeat* would be a reasonable SDK extension; the adapters and the protocol verbs are Tool-specific.
